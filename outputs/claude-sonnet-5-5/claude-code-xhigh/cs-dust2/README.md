# DUST2 · 5v5 FPS 原型

React 18 + TypeScript + three.js 从零实现的浏览器第一人称射击原型：复刻 Dust2 核心区域的 5v5 对战（1 名玩家 + 4 名 AI 队友 vs 5 名 AI 敌人）。

**零外部资源**：没有任何模型 / 贴图 / 音频文件。地图、角色、武器全部用代码生成几何体，纹理用 Canvas 程序化绘制，声音用 Web Audio 实时合成。第三方库只有 `three`、`react`、`react-dom`；寻路、AI 状态机、物理、回合逻辑、渲染循环全部自己实现，没有使用任何游戏引擎。

```bash
npm install
npm run dev        # 打开 http://localhost:5173 ，点击"开始比赛"，再点击画面锁定鼠标
```

需要 Node ≥ 22.6（仅测试脚本需要，用于直接运行 TypeScript；`vite` 本身不依赖它）。

## ⚠️ 验证状态（请先读这一段）

这个项目是在**无法访问 npm registry 的沙箱**里写的（`npm install` 被网络策略拒绝，也没有离线缓存），所以：

| 部分 | 状态 |
|---|---|
| 模拟核心（地图、物理、寻路、武器、AI、回合 / C4 / 经济逻辑） | ✅ **真实运行并测试**：`npm run test:sim`，166 项断言全部通过 |
| 表现层（three 渲染、Web Audio、输入、会话循环、HUD 数据流） | ⚠️ **只做了冒烟测试**：`npm run test:smoke`（45 项）把这些代码跑在 *three / DOM / Web Audio 的仿真替身*上，能证明代码流程无异常、无 NaN、音频参数合法、数据流打通；**不能证明真实 WebGL 画面、CSS 排版、音色好不好听** |
| React 组件（`src/ui/*.tsx`）、`vite` 打包、`tsc` 类型检查 | ❌ **从未运行过**（需要安装依赖） |

因此第一次在你的机器上跑起来时，可能遇到我这里看不到的问题（three API 用法细节、类型错误、视觉调优）。建议顺序：`npm install` → `npm run typecheck` → `npm run test` → `npm run dev`。`npm run build` 只调用 `vite build`（不含 tsc），所以即使有类型报错也不会阻塞打包。

## 需求对照

**Dust2 地图**（`src/core/map/dust2.ts`，1 单位 = 1 米，120×128 m）：T 出生点、CT 出生点、A大（带坡度的长廊 + 蓝色集装箱）、A点（高台）、中门（**会自动滑开的双开门体**，有碰撞，可被玩家/AI 穿过，关闭时挡子弹和视线）、猫道（上坡通往 A）、B洞（外 B洞 → 上 B洞 → 出口坡道，另有下 B洞连接中路）、B点、中路 / 下 B 通道 / CT 中路。所有区域按 Dust2 走位互相连通，测试用 A* 逐条验证（`T_A_LONG`、`T_A_CAT`、`T_B_TUNNELS`、`T_B_LOWER`、`T_B_MID`、`T_MID_DOORS`、`CT_A`、`CT_B` …）。所有墙体、箱子、门、斜坡都有碰撞；地图由"挖矩形"声明式构建，墙壳自动生成，因此**构造上就是封闭的**。

**角色**（`src/render/characterModel.ts`）：类人型，独立的头、躯干、双臂（上臂+前臂+手）、双腿（大腿+小腿+靴子），全部由方块拼成，有走路周期、瞄准俯仰、持枪姿势、蹲姿、倒地动画。CT = 蓝色制服 + 头盔护目镜；T = 卡其色制服 + 黑色面罩 + 头巾，一眼可辨。武器挂在胸前插槽，随朝向/俯仰移动。

**武器系统**（`src/core/weapons/`）：数据驱动，`registerWeapon(def)` 即可扩展；每把枪的第一人称/第三人称模型也是数据（`models.ts` 里的零件列表）。

| 武器 | 伤害 | 弹匣 | 射速 | 特点 |
|---|---|---|---|---|
| AK-47 | 40 | 30 | 600 rpm | 高伤害；每发上扬 1.75°，准星扩散增长快 |
| M4A4 | 36 | 30 | 680 rpm | 中等伤害；后坐力仅 0.7°，射速更高 |
| AWP | 150 | 10 | 41 rpm | 任何部位一枪致命；右键开镜（FOV 40° / 12°），未开镜极不精准 |
| Glock-18 (T) | 18 | 20 | 半自动 | 手枪局默认 |
| USP-S (CT) | 21 | 12 | 半自动 | 手枪局默认，消音 |
| Desert Eagle | 28 | **7** | 半自动 | 伤害介于手枪与步枪之间，后坐力大 |
| 匕首 | 40 / 65 / 背刺 180 | – | – | 左键劈砍，右键刺击 |

命中判定按 Hitbox 分区（头 / 胸 / 腹 / 手臂 / 腿，随角色朝向旋转，蹲下压扁），倍率 `2.0 / 1.0 / 1.25 / 0.8 / 0.7`，**爆头恰好是胸部（身体）伤害的 2 倍**（有测试）。护甲按 CS 公式减伤（头部需头盔，腿部无保护），另有距离衰减。

**手枪局**：`ROUND_PRESETS.pistol`（`src/core/config.ts`）——全员只带默认手枪 + 匕首、无主武器、护甲 0、起始资金 $800，之后自动进入经济回合（赢/输奖励、连败补偿、击杀奖励、eco / 强起 / 全起决策）。也可选"全装局"。

**C4 与回合**：回合开始 C4 随机交给某个 T；持包者阵亡掉落，其他 T 走近自动拾取；在 A/B 点范围内按住 `E` 3.2 秒安放（离开/松手中断）；CT 按住 `E` 10 秒（拆弹器 5 秒）拆除。胜负：T 全灭 CT 或 C4 爆炸 → T 胜；CT 全灭 T（且未下包）或拆除成功 → CT 胜；时间到未下包 → CT 胜；下包后 T 全灭则继续，CT 必须拆除。玩家死亡后自动观战存活队友，可按 `F` 接管其 bot。

**5v5 AI**（`src/core/ai/`）：
* 基于碰撞世界**自动生成**的 0.5 m 导航网格 + A*（离墙惩罚使其走在通道中央）+ 净空感知的路径平滑，不依赖手摆路点；带卡住检测与脱困。
* 分层状态机：`idle / travel / hold / engage / search / plant / defuse / pickup / dead`。
* 感知：视野锥 + 射线遮挡判定（被墙/门挡住看不见）、听觉（枪声/脚步/下包/拆包）、队伍情报共享。
* 战斗：反应时间、平滑瞄准与瞄准误差、后坐力补偿、点射 / 急停射击 / 侧移、AWP 开镜、近距离换手枪。bot 与玩家走**同一套** `UserCmd → 移动 / 武器 / 后坐力 / 扩散`代码，没有作弊。
* 战术：T 每回合选 A 大 + 猫道 / B 洞 / 中路 B / 分推等方案，在集结点等待统一"执行时间"；CT 每回合随机选防守站位（均分 / 重 A / 重 B），中路 CT 负责转点；下包后 T 转守包并在爆炸前撤离，CT 集结后统一回防；持包 T 前往包点安放，最近的 T 去捡掉落的包。

**HUD**（`src/ui/`）：动态十字准星（间隙跟随实时精度）、生命/护甲、动态弹药面板（开火递减、换弹进度条）、右上角击杀播报、顶部计分/计时/存活数、命中标记 + 爆头标记、受击方向指示、AWP 镜头遮罩、安放/拆除进度条、购买菜单、计分板、观战栏、暂停面板。**小地图**：常驻显示 Dust2 俯视轮廓（按高度着色的地形、箱子、门、点位标签），实时标出自己（带视野扇形）、队友、被队友看见的敌人，以及 C4（掉落 / 已安放；T 方携带者带黄环）。

**声音**（`src/audio/audioEngine.ts`，全部程序化合成，带 3D 定位与距离低通）：AK / M4 / AWP（含拉栓声）/ Glock / USP（消音）/ 沙鹰各不相同的开火声、换弹（退匣 / 插匣 / 拉栓）、脚步、AWP 开镜、命中反馈（爆头与身体不同）、受击、C4 安放 / 滴滴 / 拆除 / 拆除完成 / 爆炸、击杀提示音、门滑动、回合开始/结束提示。

## 架构

```
src/
  core/            ← 与渲染无关的模拟核心（可在 Node 里无头运行和测试）
    map/           声明式关卡构建器 + Dust2 布局
    physics/       碰撞世界（空间哈希 + 斜坡 + 滑动门 + 射线）、角色控制器
    nav/           自动生成的导航网格、A*、路径平滑
    weapons/       武器数据、命中箱与伤害公式、运行时状态
    ai/            bot 大脑（状态机）+ 团队战术
    game/          回合状态机、经济、C4、战斗、事件流
  render/          three.js：合并静态网格、程序化纹理、角色/武器模型、第一人称手臂、特效、相机
  audio/           Web Audio 合成
  app/             GameSession（主循环）、输入、HUD 数据存储
  ui/              React 组件（HUD、菜单）、小地图绘制
scripts/           无头测试与开发工具
```

**三者如何同步**（渲染循环 / 物理帧更新 / React 状态）：

1. **模拟**以固定 60 Hz 步进（`Game.advance(dt)` 累加器），所有游戏规则只在这里发生。
2. **渲染**每个 `requestAnimationFrame` 执行一次：用 `alpha = 累加器 / tick` 在前后两个 tick 之间插值角色位置，相机偏航/俯仰直接读最新值（鼠标输入即时生效，不经过 tick）。
3. 模拟把发生的一切写入**事件流**（`shot / hit / kill / plant / explode …`），渲染层（曳光、弹孔、血、爆炸）、音频层、HUD 只是这个流的消费者，都不修改模拟。
4. **React** 只收到一份节流（10 Hz）、去重的不可变快照（`useSyncExternalStore`）；每帧都要变的东西（准星间隙、小地图）通过 `session.onFrame` 回调直接改 DOM / Canvas，因此 React 不会以 60 Hz 重渲染。
5. `GameView` 在 `useEffect` 中创建 / 销毁整个 `GameSession`（模拟 + 渲染器 + 音频 + 输入监听），StrictMode 安全。

关卡里的光照是**烘焙进顶点色**的（固定太阳方向 + 竖直渐变的廉价环境遮蔽）并用 `MeshBasicMaterial` 绘制：不需要灯光，外观确定，性能开销极小。

## 测试与开发工具

```bash
npm test                 # test:sim + test:smoke
npm run test:sim         # 模拟核心，166 项：地图连通、碰撞、寻路、武器数值、爆头 2 倍、护甲、
                         #   手枪局配置、C4 全流程、回合胜负、旁观/接管、整局 bot 对战无穿墙
npm run test:smoke       # 表现层冒烟测试（three/DOM/Web Audio 仿真替身，见上文说明）
npm run sim:ascii        # 把地图打印成 ASCII 看布局
npm run sim:match -- 6 1 pistol v     # 无头跑整局，打印每个回合和击杀
npm run sim:balance -- 16 8 fullbuy   # 多局统计：胜率、下包率、拆包/爆炸次数
node --experimental-strip-types scripts/duel.ts 300 ak47 m4a4 20   # 武器 1v1 公平性
node --experimental-strip-types scripts/clash.ts 80 30              # 5v5 团战公平性
```

无头统计（普通难度，bot 对 bot，`sim:balance`，仅供参考）：全装局 CT 52% / T 48%；手枪模式前 8 回合 CT 39% / T 61%（手枪局第 1 回合 CT 约 30%，之后是经济循环；人类玩家会让自己一方更强）。约 58–63% 的回合会出现下包，并出现拆除、爆炸、超时等多种结局。

## 已知限制

* 没有半场换边、投掷物、穿墙射击、掉落武器拾取。
* 手枪局第 1 回合偏向 T；可以在 `src/core/ai/brain.ts` 顶部的 `TUNING` 与 `skillFor` 里调整 AI。
* 地图是 Dust2 核心区域的简化重构（不是逐面还原）；B 窗、B 门、坑（Pit）等细节没有做。
* 视觉效果与手感没有在真实浏览器里调过（见"验证状态"）。
