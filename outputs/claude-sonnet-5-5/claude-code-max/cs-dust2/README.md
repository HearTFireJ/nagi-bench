# Dust2 · 5v5 FPS 原型（React 18 + TypeScript + three.js）

在浏览器里直接游玩的 3D 第一人称射击原型：复刻 Dust2 核心区域的 5v5 对战（1 名玩家 + 4 名 AI 队友 vs 5 名 AI 敌人）。
**没有任何外部资产**：地图、角色、武器全部由代码几何体程序化生成，声音由 Web Audio 实时合成；第三方库只有
`three` / `react` / `react-dom`，寻路、AI 状态机、物理、渲染循环、状态管理全部自己实现。

## 运行

```bash
npm install
npm run dev        # 打开 http://localhost:5173 ，点击「开始游戏」（会锁定鼠标）
npm run build      # 生产构建
npm run typecheck  # tsc --noEmit
```

需要 Node 18+；开发用的检查脚本（见下文）需要 Node 22.18+（内置 TypeScript 类型剥离）。

> **重要：请先读「验证情况」一节。** 交付时的环境无法访问 npm registry，所以这份代码**没有在真实浏览器里跑过**，
> 也**没有跑过 `tsc`**。逻辑层（模拟）有完整的无头测试；渲染/UI 层只做了冒烟测试。

## 操作

| 按键 | 功能 |
| --- | --- |
| `W A S D` / `空格` / `Shift` | 移动 / 跳跃 / 静步（无脚步声，更慢） |
| 鼠标 / 左键 / 右键 | 视角 / 开火 / AWP 开镜（FOV 40° ≈ 2×；再按一次 FOV 12° ≈ 7×；第三次取消） |
| `R` `1` `2` `3` `5` `Q` `G` 滚轮 | 换弹 / 主武器 / 手枪 / 刀 / C4 / 上一把 / 丢弃 / 切枪 |
| 按住 `E` | 在 A/B 点安放 C4（持包 T）、拆除 C4（CT）、拾取地上的武器 |
| `B` | 准备阶段购买菜单（数字键购买；手枪局锁定） |
| `Tab` | 计分板 |
| 阵亡后 `←` `→` 或鼠标左右键 | 切换观战的存活队友 |
| 阵亡后 `F` | **接管**当前观战的队友 bot |

`Esc` 释放鼠标并暂停（模拟冻结）；点击继续。若浏览器拒绝指针锁定（如 iframe 内），连续两次失败后会自动降级为普通鼠标视角，`Esc` 依然可暂停。

## 架构

```
                 ┌───────────────────────── src/game  (纯逻辑，无 DOM / three / React，可在 Node 里无头运行) ─────────────────────────┐
                 │ World: 固定 60Hz 步进                                                                                               │
 输入 ─actor.input─►│  ├ 机器人大脑(ai/brain.ts)   ├ 移动物理(movement.ts + collision.ts)   ├ 战斗(combat.ts)   ├ 炸弹(bomb.ts)      │
                 │  └ 回合/经济(world.ts, loadout.ts)         ──► events (Emitter<GameEvent>)                                          │
                 └───────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┘
                                                                              │ 读取状态 + 订阅事件
            ┌──────────────────────────────┬─────────────────────────────┬────┴─────────────┬────────────────────────────┐
            │ render/GameRenderer (three)   │ audio/Sfx (Web Audio 合成)   │ engine/hudBuilder │ ui/* (React, 只订阅 store)   │
            └──────────────────────────────┴─────────────────────────────┴──────────────────┴────────────────────────────┘
                                             engine/GameEngine: rAF 循环 = 累加器 → 固定步 → 插值渲染
```

**渲染循环 / 物理帧 / React 生命周期的同步**（`src/engine/GameEngine.ts`）：

- rAF 里用**累加器**跑固定 1/60 s 的模拟步；渲染用 `alpha = acc / SIM_DT` 在上一步与当前步之间**插值**位置，高刷屏也平滑。鼠标视角在每帧开头直接写入被控角色（低延迟），不经过 React。
- 输入(`input/controls.ts`)每帧写入被控角色的 `ActorInput`：按住的键是电平，按下的动作是**边沿标志**，由模拟消费后清除。机器人的大脑写的是**同一个结构**——bot 与玩家遵守完全相同的物理和武器规则。
- 模拟通过**事件**(`GameEvent`)通知外界；音频、特效、击杀播报、命中标记都是订阅者，模拟本身不知道它们的存在。
- React 不在热路径上：引擎以约 15 Hz 把不可变的 `HudState` 快照发布到外部 store(`state/store.ts`)，且只在内容变化时换引用（`stabilize`，嵌套对象保持引用稳定）；组件用 `useSyncExternalStore` 按选择器订阅切片。准星间隙、小地图、命中标记、受击方向这类**高频**内容完全命令式（`frame$` / `ui$` 事件 + 直接写 DOM/canvas），不产生 React 重渲染。
- 生命周期：`App` 在 `useEffect` 里创建/销毁**一个** `GameEngine`（StrictMode 双挂载安全：dispose 会取消 rAF、移除全部监听、释放 WebGL/AudioContext）。

## 地图（`src/game/map`）

关卡用**带高度的可走矩形区域**描述（米，x 向东、z 向南，108×104 m）：先在 0.5 m 栅格上栅格化，再给每个可走格周围挤出 1 m 厚的墙壳、合并成尽量少的碰撞盒，所以**关卡天然封闭**；再叠加箱子、屋顶（B 洞）、滑动中门与命名锚点。A 点高台（+1.6 m）通过 A 大长坡、猫道楼梯、CT 坡三条阶梯通道到达（台阶 0.2 m，角色自动上台阶）。视线审计脚本保证没有贯穿全图的直线狙击道（最长约 62 m，与真实 Dust2 相当）。

- **中门**：两扇滑动门叶是真实的动态碰撞盒（关闭时挡人、挡子弹、挡视线），5 m 内有人就打开，无人 1.2 s 后关闭。
- 导航栅格由**碰撞世界自动生成**（考虑 0.3 m 身体半径 + 余量，忽略可自动踏上的低台阶），所以路径与物理一致；单一连通分量，所有区域、锚点、出生点从 T/CT 两侧都可达。

## 武器数值（`src/game/weapons.ts`）

| 武器 | 伤害 | 射击间隔 | 弹匣/备弹 | 后坐力（视角上扬/枪） | 备注 |
| --- | --- | --- | --- | --- | --- |
| AK-47 | 50 | 0.100 s（全自动） | 30/90 | 1.35°，累计上限 15°，扩散最大 | 无甲爆头一枪 |
| M4A4 | 36 | 0.085 s（全自动） | 30/90 | 0.55°，上限 6° | 射速最高、最稳 |
| AWP | 200 | 1.45 s（栓动） | 10/30 | 4°，单发 | 任意命中区都致命；开镜 40°/12°，未开镜散布很大 |
| Glock-18 | 22 | 0.15 s（半自动） | 20/120 | 0.85° | T 默认 |
| USP-S | 26 | 0.17 s | 12/24 | 0.8° | CT 默认 |
| Desert Eagle | 34 | 0.225 s | 7/35 | 2.6° | 伤害介于手枪与步枪之间，弹匣最小 |
| 刀 | 40 / 右键 65 | 0.5 / 1.1 s | – | – | 近战 |

命中区倍率：**头 ×2.0**、胸 ×1.0、腹 ×0.9、臂 ×0.7、腿 ×0.55（互不相同，爆头恰为胸部“身体”的两倍）。伤害流程：基础伤害 → 区域倍率 → 距离衰减 → CS 风格护甲吸收（每把枪有 `armorRatio`；头部需头盔，腿部不受护甲保护）。

## AI（`src/game/ai`）

- **感知**：水平视野锥 ±65°（5 m 内无视朝向）+ 头/胸/腿三点射线对碰撞世界的遮挡判断（墙、关闭的门都会挡住）；听到枪声（45 m）和跑步脚步声（13 m）会转向声源；队友接敌会互相通报。
- **状态机**：`freeze / travel / hold / search / engage / plant / defuse / cover / stage / fetch / guard`。战斗时按武器类型开火：步枪按后坐力决定点射长度，手枪逐发点射，AWP 先开镜且站稳再射；停火射击、间隙横移；反应时间、瞄准误差、后坐力补偿由 `skill` 决定。
- **战术**：T 每回合随机一套进攻（A 大 rush / 中路猫道 / B 洞 / 中转 B / 分路），同组等待队友避免零散送人头，携包者下包；掉包后**指定唯一**的队友去捡；下包后在能看见炸弹的位置布防。CT 随机一套防守站位（A/B/中门），下包后离炸弹远的先在集结点会合再压上、最近的先拆、其余掩护。
- **寻路**：8 邻域 A\*（贴墙代价）+ 拉直平滑；跟随时有卡住检测（跳 → 重规划 → 最后手段传送）和局部避障。无头测试里 99 回合的卡住救援合计 7 个 tick、0 次重规划、0 次传送。

## 验证情况（诚实说明）

**交付环境无法访问 npm registry（沙箱返回 403，也不允许放开白名单），所以没有执行 `npm install`。** 因此：

已经做过的（都能用 `npm run …` 复跑）：

| 命令 | 验证内容 | 结果 |
| --- | --- | --- |
| `npm run check:nav` | 导航栅格单一连通；所有锚点/区域/出生点从 T 与 CT 双向可达；路径长度 | 通过 |
| `npm run check:phys` | 用真实移动物理沿导航路径走 50 对起终点（含台阶、坡、开门）；射线检测对比暴力枚举 3000 条 | 50/50，3000/3000 |
| `npm run check:rules` | 60 余条规则断言：五个命中区倍率各异且头 = 2×胸、AWP 任何部位一枪致命、AK/M4 后坐力与射速差异、手枪局装备、下包/拆包/爆炸/掉包/捡包/淘汰/超时的回合结算、中门开关与穿过 | 全部通过 |
| `npm run sim` / `npm run balance` | 全 bot 无头整场对战：回合完整结算、无人陷进墙里或出界；100 回合级别的胜率/卡住统计 | T 胜率约 37%（CT 略占优） |
| `npm run check:los` | 全图长视线审计 | 最长约 62 m |
| `npm run smoke` | **用假的 three / DOM / WebAudio 桩**真实执行整条浏览器代码路径（GameEngine → GameRenderer → 角色/视角模型/特效/音频/输入/HUD 构建）数千帧，并用合成的键鼠事件驱动：开局、走、看、射、换弹、切枪、开镜、死亡、观战、接管、暂停/恢复、指针锁定被拒的降级、销毁；桩会检查所有变换/几何是否为有限数 | 通过 |
| `npm run check:winding` / `check:reach` | 方块面绕序（否则会被背面剔除而“消失”）；所有武器双手是否够得着 | 通过 |
| 打包检查 | 用 bun 把全部 47 个模块（three/react 设为 external）打包，验证语法与导入/导出一致 | 通过 |

**没有做到的**（请你在本地确认）：

1. **没有在真实浏览器/GPU 上运行**：画面观感（配色、光照、贴图、模型比例）、音效听感、指针锁定的真实行为、React 组件的实际渲染，都没有亲眼验证。three 的用法是按 r169 API 手写的，桩只能验证“不抛异常、变换有限”，不能替代真实渲染。
2. **没有运行 `tsc`**。代码按 `strict` 编写，但可能存在少量类型小问题；`npm run dev` / `npm run build` 只经过 esbuild 转译，不做类型检查，所以不受影响，`npm run typecheck` 可能需要你顺手修几处。
3. React 组件（`src/ui`）没有在 React 里实际渲染过，只通过了打包检查和阅读审查。

## 已知限制 / 取舍

- 没有半场换边、手雷/闪光/烟雾、蹲伏、穿墙射击；角色之间没有互相碰撞（避免 bot 相互卡住）；bot 不会爬箱子（玩家可以）。
- 友军伤害关闭，子弹穿过队友。
- 数值是为“手感差异明确”调的，不是逐点复刻 CS：AWP 伤害设为 200，保证任何命中区（含腿）都致命；AK 设为 50（无甲爆头一枪）以维持与 M4 的强弱。
- 机器人对战胜率 T≈37%，CT 略占优；`world.ts` 里给 T 方 bot 加了一个小的“进攻方技术补偿”（`sideBonus`）。
- 第一回合手枪局全员**不可购买**（保证“全员只带默认手枪、护甲按手枪局配置”），从第二回合起有完整的金钱、购买和连败补偿。
